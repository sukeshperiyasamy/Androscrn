Quick Start

Get Running in Minutes

Use the portable ZIP for zero-install setup, or build from source for development.

Method 1: Portable No-Installer ZIP (Recommended for Users)

Zero installation required. Does not require Node.js, npm, Python, Java, or Android Studio. Bundles all required Electron runtimes, ADB, and scrcpy binaries out-of-the-box.

STEP 1

Download & Extract

Download AndroScrn-portable-win-x64.zip from official GitHub Releases, or generate it locally in 10s with npm run build:portable. Extract to any folder (e.g. C:\Tools\AndroScrn).

STEP 2

Run Directly

Double-click AndroScrn-gui.exe to open the desktop workbench immediately, or open CMD / PowerShell in the folder and type androscrn.

STEP 3 (OPTIONAL)

Add to User PATH

Run androscrn setup-path to use the CLI from any terminal without administrator rights. Remove cleanly anytime with androscrn remove-path.

System Prerequisites

  • OS: Windows 10 or 11 (x64)
  • Node.js: v20.x or higher
  • Android Device: Physical hardware or emulator (Android 8.0+ for screen mirroring, Android 12+ for native scrcpy camera mode)
  • Bundled Binaries: scrcpy 5.0.1 and ADB are included in the repository

Device Debugging Setup

  1. Open Settings > About Phone and tap Build Number 7 times.
  2. Navigate to Developer Options and toggle USB Debugging to ON.
  3. Connect via USB cable and tap Always Allow on the RSA fingerprint dialog.
  4. Xiaomi/Redmi/POCO Users: Additionally enable USB debugging (Security settings) to permit simulated input injection.

Standalone MCP Client Setup

To connect Claude Desktop or Cursor to AndroScrn's stdio MCP server, register the command in your MCP configuration file:

"androscrn": { "command": "node", "args": ["packages/mcp-server/dist/index.js"] }

Two Implementation Paths for Camera Control

Path 1: App-Free Camera Mode

scrcpy 5.0.1 Native

Uses built-in scrcpy 5.0.1 camera mirroring (--video-source=camera) through standard ADB.

  • Zero Installation: No APK required on the phone.
  • Controls Supported: Lens switching (--camera-id), zoom (--camera-zoom), and torch (MOD+t).
  • Requirement: Requires Android 12+ (API 31+) device support.
scrcpy --video-source=camera --camera-id=0 --camera-zoom=2.5

A proposed dedicated lightweight Android application built on CameraX and Camera2 APIs.

  • Pro-Grade Optics: Manual focus distance, manual exposure compensation, and ISO selection.
  • Broad Compatibility: Supports devices running Android 8.0+ through 14+.
  • Transport: Low-latency socket or WebRTC stream paired via authenticated HMAC handshake.

Security & Privacy

Safety-First Android Governance

Automation without oversight invites risk. AndroScrn implements bounded operations, operator consent, and automated redaction.

Human-in-the-Loop (HITL) Gatekeeper

High-impact Tier 3 input tools (tap, swipe, keyevent, input_text) require manual human approval in the desktop UI before execution.

Time-Bound Sessions

Approved pairing sessions automatically expire after 5 minutes. Revocation occurs immediately upon inactivity, app exit, or manual cancellation.

Instant Emergency Revocation

A dedicated kill switch in the desktop UI and MCP toolset (revoke_pairing) invalidates all active tokens within 10 milliseconds.

IPC Hardening

The named pipe (\\.\pipe\androscrn-mcp-control) restricts maximum message sizes to 64KB, rejects multi-client overlaps, and prevents buffer overflow attacks.

Sensitive Data Redaction

Automated regex filters sanitize bearer tokens, Authorization headers, passwords, and sensitive device serials from Logcat and MCP tool responses.

Transparent Threat Model

We document real limitations: USB debugging grants root-adjacent privilege. AndroScrn protects local IPC boundaries, but requires trusted host workstations.

Frequently Asked Questions

Common questions regarding hardware compatibility, debugging requirements, security, and setup.

AndroScrn is optimized for Windows 10 and 11 (64-bit). Android screen mirroring and ADB diagnostics support Android 8.0 (Oreo) and above. Native app-free camera streaming via scrcpy requires Android 12 (API 31) or newer due to Android camera HAL service requirements.
No. In its current implementation, AndroScrn is completely app-free on the phone. It utilizes the bundled scrcpy server executed dynamically over ADB. An optional Camera Companion APK is on the roadmap to enable manual exposure/ISO controls and support older Android versions, but it will remain entirely optional.
MIUI and HyperOS include an additional vendor security permission. To allow automated taps and swipes, you must enable both USB Debugging and USB Debugging (Security settings) in Developer Options. The latter requires an active SIM card and Xiaomi account authorization.
AndroScrn isolates read-only tools (battery, screenshot, logcat) from high-impact input tools (tap, swipe, keyevent). All input tools require an approved pairing session token from the desktop UI. Sessions expire after 5 minutes and can be revoked instantaneously with a single click.
Yes. You can connect devices wirelessly using standard ADB TCP/IP (adb tcpip 5555 followed by adb connect <device-ip>:5555). For lowest latency and high-bitrate camera streaming, a USB 3.0 cable connection is recommended.
Screenshots and recordings triggered through the desktop UI are saved directly to your local user directory on Windows (C:\Users\<username>\Videos\AndroScrn or within the project capture folder), ensuring no files take up storage on the Android device.

Privacy Policy Highlights

Zero Telemetry Localhost Only

AndroScrn enforces a strict local-first privacy standard. We do not collect, transmit, sell, or analyze your device data, screen contents, camera streams, or personal documents.

Data Category Desktop Workbench Practice Android Companion Practice
Device Telemetry Held strictly in volatile desktop RAM; auto-redacted in diagnostic exports (masks serials, MACs, Wi-Fi SSIDs). Does not query or transmit device identifiers. Binds exclusively to loopback 127.0.0.1.
Screen Mirroring Decoded directly onto desktop surface via Direct3D11; captures saved only to user-chosen Windows folders. Standard Android display capture managed via system ADB server.
Camera Sensor Feed Displays live stream on PC; captures saved to user directory. No cloud routing. MJPEG stream in RAM; full-res stills saved to app cache and deleted immediately (tempFile.delete()).
OCR & Document Text Local WebAssembly Tesseract OCR (@tesseract.js-data/eng); strictly zero network requests verified. Not applicable (OCR runs 100% on desktop host).
Pairing & Auth Tokens Tokens stored in memory; revoked with 1 click in Security Center. Out-of-band 6-digit PIN on phone screen (60s TTL); 64-char volatile bearer token; 3-try lockout.
Anti-Covert Protections Active camera status clearly indicated in UI header. Prominent, permanent LIVE FEED ACTIVE banner displayed on phone screen.
